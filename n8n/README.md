# مواصفات ودليل تكامل n8n: Paperless → Google Drive → Google Sheets

تحدد هذه الوثيقة مواصفات التكامل الآلي أحادي الاتجاه لنشر الوثائق المؤرشفة والمعتمدة رسمياً من محرك Paperless-ngx المحلي إلى Google Drive (لحفظ النسخة المعتمدة) وإلى Google Sheets (كفهرس بحث وسجل مركزي).

## مبادئ الحماية والتصميم المعماري

1. **نشر أحادي الاتجاه فقط (One-Way Sync)**: لا تُنقل أي تعديلات أو بيانات من Google إلى Paperless إطلاقاً.
2. **شروط الاعتماد الصارمة (Publication Preconditions)**:
   - الحقل المخصص `معتمد للمزامنة` قيمته `true` حصراً.
   - خلو المستند تماماً من وسم `بانتظار المراجعة` (Inbox Tag).
   - وجود وسم قسم واحد فقط من الأقسام المعتمدة (`شخصي`، `الرنين`، `تناسق`، `NAS FM`).
   - اكتمال الحقول الإلزامية: `رقم الكتاب` (نص يحفظ الأصفار والشرطات مثل `0042/ص-2026`)، `الجهة المرسلة`، `الجهة المستلمة`، `راجعه`، و`تاريخ المراجعة`.
   - وجود عنوان للمستند (الموضوع) وتاريخ إنشاء (تاريخ الكتاب).
3. **بصمة الاعتماد (Approved Hash Integrity)**:
   - تُحسب بصمة أمان رقمية (SHA-256) تجمع محتوى الملف الأصلي مع جميع بيانات الحقول المعتمدة.
   - أي تعديل لاحق على محتوى الوثيقة أو حقولها الرسمية يغير البصمة، ويوقف المزامنة تلقائياً حتى يُعاد تدقيقها واعتمادها يدوياً.
4. **منع التكرار وسجل المزامنة الدائم (Idempotent Ledger)**:
   - مفتاح مستقر فريد: `instance_id:document_id`.
   - تخزين حالة المزامنة في سجل SQLite دائم (`sync_ledger`).
   - **الترتيب الإلزامي للعمليات**:
     1. التحقق من شروط الاعتماد وقفل السجل (`PENDING`).
     2. البحث في Drive عن ملف يحمل `sync_key` في `appProperties` (لمنع التكرار عند حدوث مهلة شبكة سابقة).
     3. رفع الملف إلى مجلد `القسم/السنة`.
     4. **حفظ `drive_file_id` فوراً في السجل** وتحديث الحالة إلى `DRIVE_UPLOADED`.
     5. تحديث صف الفهرس في Google Sheets.
     6. تسجيل النجاح التام وتحديث الحالة إلى `SYNCED`.
   - **استئناف الفشل**: في حال نجاح الرفع إلى Drive وفشل خطوة Sheets (بسبب انقطاع الشبكة أو حد الطلبات)، تستأنف المحاولة التالية تحديث Sheets مباشرة باستخدام `drive_file_id` المحفوظ، **دون إعادة رفع الملف إلى Drive نهائياً**.
5. **سياسة الروابط والأمان**:
   - لا يتم إنشاء أي روابط عامة أو مشاركة للملفات على الإنترنت؛ الروابط داخلية لحساب العمل فقط.
   - لا يوجد حذف آلي سحابي للملفات عند سحب الاعتماد أو حذف المستند محلياً؛ يُسجل الإلغاء وتُحال المعالجة إلى مراجعة بشرية.

## بنية أعمدة فهرس Google Sheets (16 عموداً)

| الرقم | اسم العمود | الوصف والبيانات |
|---|---|---|
| 1 | `مفتاح المصدر` | المفتاح المستقر الفريد (مثل `nas-prod:42`) |
| 2 | `القسم` | اسم القسم (`شخصي`، `الرنين`، `تناسق`، `NAS FM`) |
| 3 | `نوع الكتاب` | نوع المستند (`كتاب وارد`، `كتاب صادر`، `كتاب داخلي`) |
| 4 | `رقم الكتاب` | رقم الكتاب الرسمي كنص صريح يحفظ الأصفار والشرطات (مثل `0042/ص-2026`) |
| 5 | `الموضوع` | موضوع الكتاب (عنوان المستند) |
| 6 | `تاريخ الكتاب` | تاريخ إصدار الكتاب الرسمي (YYYY-MM-DD) |
| 7 | `المرسل` | الجهة المرسلة |
| 8 | `المستلم` | الجهة المستلمة |
| 9 | `تاريخ الورود` | تاريخ ورود المعاملة (YYYY-MM-DD) |
| 10 | `رقم القيد` | رقم القيد الداخلي (نص) |
| 11 | `المراجع` | اسم الشخص الذي دقق واعتمد الوثيقة |
| 12 | `تاريخ المراجعة` | تاريخ التدقيق والاعتماد (YYYY-MM-DD) |
| 13 | `رابط Drive` | رابط الوصول المباشر للمستند في Google Drive |
| 14 | `رابط Paperless` | رابط الوصول المحلي للمستند في Paperless-ngx (`http://localhost:8000/...`) |
| 15 | `بصمة النسخة` | تجزئة SHA-256 المعتمدة للوثيقة وبياناتها |
| 16 | `وقت المزامنة` | التوقيت الزمني للمزامنة بصيغة ISO UTC |

## المتطلبات الخارجية للتفعيل النهائي (تتطلب تدخلاً خارجياً)

قبل تفعيل n8n وتشغيل خط الإنتاج السحابي الحقيقي، يلزم توفير المدخلات الخارجية التالية:
1. **Google Cloud Service Account أو OAuth Client**:
   - تفعيل Google Drive API وGoogle Sheets API.
   - تنزيل ملف بيانات الاعتماد `credentials.json` ومنحه صلاحيات الكتابة.
2. **معرفات مجلدات Google Drive**:
   - إنشاء مجلدات رئيسية للأقسام والحصول على Folder ID لكل منها.
3. **جدول Google Sheets المخصص**:
   - إنشاء جدول الفهرس وتسمية الورقة وإعداد رؤوس الأعمدة الـ 16 المحددة أعلاه، والحصول على `Spreadsheet ID`.
4. **بيئة تشغيل n8n**:
   - إما تشغيل n8n محلياً كخدمة Docker مستقلة بمفتاح تشفير محفوظ، أو ربطه بنسخة n8n سحابية معتمدة.
