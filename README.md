# NAS Archive

مرحلة تأسيسية لأرشيف محلي على Windows. يعمل Paperless-ngx كمحرك مستقل من صورته الرسمية؛ لا توجد نسخة معدلة من upstream. Google Drive وSheets وجهتا نشر لاحقتان، وPaperless هو المصدر الأساسي.

## التشغيل

المتطلبات: Docker Desktop يعمل بحاويات Linux وWSL 2، وPython 3.12 أو أحدث لتأسيس البيانات. افتح PowerShell داخل هذا المستودع.

```powershell
./scripts/Initialize.ps1
docker compose config --quiet
docker compose pull
./scripts/Test-Runtime.ps1
python scripts/provision_local.py
```

يفتح النظام على http://localhost:8000 فقط. التهيئة تولد أسراراً عشوائية محلية وتحافظ عليها عند الإعادة. لا ترفع `.env` أو `runtime` إلى Git. لا تستخدم `docker compose down -v` لأنه يحذف وحدات البيانات.

التأسيس المحلي ينشئ حساب nasadmin بكلمة مرور عشوائية في `runtime/admin-login.json`، ثم يطبق الكتالوج ويتحقق منه. لا يغير كلمة مرور موجودة ولا ينشئ حساباً إضافياً إذا وجد مستخدماً حقيقياً سابقاً. لا تشارك ملف بيانات الدخول؛ غيّر كلمة المرور من الواجهة بعد الاستلام. بعد تغييرها استخدم حسابك وAPI token للتأسيس اللاحق بدلاً من provision_local.py.

إذا كان لديك حساب موجود، أنشئ API token منه وضعه في متغير العملية `PAPERLESS_API_TOKEN` دون حفظه في ملف متعقب، ثم نفذ:

```powershell
python scripts/bootstrap.py
python scripts/bootstrap.py --apply
Remove-Item Env:PAPERLESS_API_TOKEN
```

الأمر الأول يعرض الإضافات المطلوبة دون الكتابة. الثاني ينشئ الأقسام وأنواع الكتب وحقولها عبر API. الإعادة لا تنشئ نسخاً مكررة؛ التعارض في تعريف موجود يوقف العمل بدلاً من تغييره. لا تشغله بالتوازي من عمليتين. أي فشل جزئي يمكن استكماله بإعادة الأمر بعد معالجة سببه.

## الأقسام والكتب

الأقسام وسوم: شخصي، الرنين، تناسق، NAS FM. يحدد المراجع قسماً واحداً لكل كتاب. الوسوم ليست عزلاً أمنياً؛ هذه المرحلة لحساب محلي واحد. قبل إضافة مستخدمين يجب تطبيق ملكية وصلاحيات المستندات واختبارها.

استخدم عنوان المستند للموضوع، وتاريخ الإنشاء لتاريخ إصدار الكتاب، ونوع المستند لوارد/صادر/داخلي. يضيف الكتالوج رقم الكتاب ورقم القيد كنص لحفظ الأصفار والشرطات، والجهتين المرسلة والمستلمة، وتاريخ الورود، ورابط الكتاب المرجعي، والملاحظات، وبيانات المراجعة والموافقة على المزامنة. الحقول تُعرّف في النظام ثم تُضاف للمستند من واجهته عند المراجعة؛ لا تُملأ تلقائياً في هذه المرحلة.

الوسم «بانتظار المراجعة» وسم Inbox يطبق على المستندات الجديدة. لا تعتبر إزالة الوسم وحدها موافقة للنشر. لا يوجد تكامل سحابي مفعل حالياً.

## NAPS2 وOCR

أنشأت التهيئة مجلدات `runtime/consume/شخصي` و`الرنين` و`تناسق` و`NAS FM`. اضبط NAPS2 على PDF و300 DPI. احفظ أولاً في `runtime/staging` ثم انقل الملف المكتمل إلى مجلد القسم على القرص نفسه. هذا يمنع التقاط PDF أثناء كتابة صفحاته؛ ويمكن الحفظ المباشر فقط بعد اختبار سلوك السكانر مع تأخير الاستقرار.

المراقبة دورية كل 10 ثوانٍ، وتشمل المجلدات الفرعية وتحوّل أسماءها إلى وسوم. OCR مضبوط على `ara+eng` مع تثبيت العربية عند تشغيل الحاوية. وضع `auto` يحافظ على النص الموجود؛ جودة OCR لملفات ممسوحة تحتاج اختباراً بصرياً ونتائج بحث فعلية. الملف يختفي من consume بعد استيراده، ويُحفظ داخل مخزن Paperless؛ consume ليس نسخة احتياطية.

## فحوص القبول

```powershell
python -m unittest discover -s tests -v
./scripts/Test-Runtime.ps1
./scripts/New-OcrSamples.ps1
python scripts/test_ingestion.py
```

الاختبارات المحلية تتحقق من سلوك التأسيس دون خادم. اختبار التشغيل يتحقق من إقلاع الخدمات وحزم OCR وصفحة الدخول. اختبار الاستيراد يستخدم بيانات الدخول المحلية وعينتين اصطناعيتين، ويتحقق من OCR والبحث ووسم القسم وInbox وبصمة الأصل ووجود PDF مؤرشف. يعيد استعمال العينات الموجودة ولا يكررها؛ تبقى عينتان تجريبيتان داخل الأرشيف. هذا لا يثبت دقة OCR لكل الكتب الحقيقية ولا اتصال سكانر NAPS2.

بعد الإقلاع: استورد PDF عربي ممسوحاً وPDF إنجليزياً غير حساسَين عبر NAPS2؛ تحقق من اختفاء ملف المصدر بعد النجاح، ووسم القسم وInbox، وفتح الأصل والنسخة المؤرشفة، والبحث عن عبارة من كل ملف. أضف الحقول وراجعها ثم أعد التشغيل وتحقق من بقاء البيانات. أعد bootstrap وتحقق أنه لا يضيف شيئاً. نفذ تجربة النسخ والاستعادة الموضحة في `docs/backup.md` قبل الاعتماد الفعلي.

راجع `docs/findings.md` للتحقق الرسمي، و`docs/integration-plan.md` للمراحل التالية. حالة التنفيذ الفعلية في `docs/status.md`.
